O trabalho consiste em comparar duas versões do serviço Link Extractor:

Implementar quatro configurações comparáveis:

| ID | API | Cache |
|---|---|---|
| A | Python | OFF |
| B | Python | ON |
| C | Ruby | OFF |

Utilizar contêineres Docker para os serviços.

Preservar a interface PHP para demonstração da aplicação completa, mas executar os benchmarks principais diretamente contra a API de extração, evitando adicionar o processamento PHP como variável de comparação.

Não presumir que essas etapas originais já forneçam as quatro configurações solicitadas.

Criar um mecanismo confiável para habilitar e desabilitar cache nas duas APIs.

No modo OFF, a API não deve consultar nem gravar no Redis.

No modo ON, a API deve consultar Redis e reutilizar os resultados armazenados.

**Importante:** limpar o Redis não significa desligar o cache.

A implementação deve permitir comprovar que os modos realmente são diferentes.

## 6. SCRIPT LOCUST

Criar um `locustfile.py` completo, documentado e testável.

**Comportamento obrigatório:**

Cada usuário virtual executa uma sequência de dez chamadas HTTP à API, uma para cada URL diferente.

A sequência deve preservar a mesma metodologia em todas as configurações.

Implementar:

- Validação de HTTP 200.
- Validação do formato JSON.
- Verificação dos resultados extraídos.
- Identificação das dez URLs.
- Tempos de espera configuráveis.
- Timeouts explícitos.
- Registro de falhas.
- Configuração de usuários e taxa de criação.
- Execução headless.
- Exportação de CSVs.
- Logs de execução.

Distinguir corretamente:

- Usuário virtual.
- Sequência de dez URLs.
- Requisição HTTP individual.
- Taxa de tarefas.
- RPS.
- Percentual de falhas.

O relatório deve explicar o script e demonstrar que os usuários realmente executaram as dez invocações exigidas.

Evitar que um teste termine antes de executar sequências completas suficientes para análise.
